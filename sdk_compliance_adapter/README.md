# Ruby compliance adapter

This adapter loads `posthog` from the checkout's `lib/` and constructs the public
`PostHog::Client`. `SDK_MODE=async` (default) uses the queue/worker;
`SDK_MODE=sync` uses the existing `sync_mode: true` per-event transport. `PORT`
defaults to 8080. Neither profile loads the Rails integration.

Capture UUIDs are generated by the SDK when omitted. The public `before_send`
callback observes the UUID for the adapter response without modifying the event.
An explicit UUID is forwarded to `capture`. Timestamp strings are parsed into
`Time` objects; UTC conversion and serialization remain SDK-owned. Compression
uses the SDK's gzip default unless `enable_compression` is supplied at init.

For sync `/capture`, HTTP 200 and `success: true` mean the native invocation
completed, not that delivery succeeded. `delivered` preserves the SDK's boolean
return value, including false after a terminal response or exhausted retries.
Errors remain visible in `/state` and mock traffic; raised exceptions still
produce HTTP 500. Async capture continues to acknowledge queue acceptance and
does not return `delivered`.

Flags use `evaluate_flags(..., flag_keys: [key]).get_flag(key)`, not the deprecated
`get_feature_flag` API. The SDK owns response parsing, retries and the real
`$feature_flag_called` event. No local-evaluation secret is configured, so the
remote profile evaluates on each action. Omitted `disable_geoip` remains omitted
when calling the SDK; explicit values are forwarded. The native SDK serializes
omitted/nil as `geoip_disable: false`, preserving the flags endpoint's existing
effective default rather than changing GeoIP lookup behavior.

## Inventory and interpretation

CI uses published harness **1.34.0**, server wire format, sequential execution, and separate
async/sync artifacts. Each profile selects **47** definitions:
30 V0 capture and 17 feature flags. Assertion failures remain advisory; a
separate inventory check requires both complete reports. V1, dedicated AI and
non-gzip codecs are unsupported and are not advertised.

The adapter declares `synchronous_capture` only for sync mode. Published harness
1.34.0 uses that capability to check five distinct events delivered immediately
in five requests, one event per request, with unique UUIDs and no extra request
on flush under
`capture.batch_format.synchronous_capture_delivers_each_event_immediately`.
Async retains `capture.batch_format.multiple_events_batched_together`.
The published harness selects between these cases using `synchronous_capture`;
the SDK workflow adds no filtering. The batch retry case inspects a retried
single-event request in sync mode, not multi-event batching.

Sync retry/error cases inspect wire traffic even when native capture returns
false for unsuccessful delivery. The adapter does not change SDK retry or
delivery behavior.

Native flags serialization explicitly carries the effective value required by the
canonical [GeoIP contract](https://github.com/PostHog/sdk-specs/blob/53e9bc16d14f973809f80049864866d5b6d9bdff/openspec/specs/capture/spec.md#requirement-client-level-geoip-control-with-per-call-override).
The [flags endpoint](https://github.com/PostHog/posthog/blob/ba1d628545b337816ba39df67e59726f099159c8/rust/feature-flags/src/handler/properties.rs#L20)
already treats omitted/null as false. No public signature or effective privacy
default changed, and the adapter does not supply a default option.

The reusable workflow is pinned to release commit
`574c029da75e96d55c11a54d942a6df983a58ea2`, whose release inputs pin specs commit
`53e9bc16d14f973809f80049864866d5b6d9bdff`. The published V1 image digest is
`sha256:43f75861fbcf5bc6c3d35511caa2be2d55274054c6071ebeb943aca0bcd0633a`.
Actual async and sync reports must each show 47/47 passing to establish compliance;
a green advisory job or inventory check alone does not prove this.

`/state` retains diagnostic limitations: transport observation covers capture
requests, not flags HTTP retries; capture counts exclude automatic flag-access
events; pending counts can retain asynchronously discarded events after terminal
errors. Wire assertions use the harness mock's requests, not these counters.
`events_flushed` is the successful-send delta during a flush, not a cumulative
count; synchronous captures have already sent before flushing.

## Running

From the repository root:

```sh
bundle exec rspec spec/sdk_compliance_adapter_spec.rb
SDK_MODE=async docker compose -f sdk_compliance_adapter/docker-compose.yml up --build --abort-on-container-exit
SDK_MODE=sync docker compose -f sdk_compliance_adapter/docker-compose.yml up --build --abort-on-container-exit
```

For a native launch, unset `STUB` (it disables SDK HTTP), set `RUBYLIB=lib`, and
run `ruby sdk_compliance_adapter/adapter.rb` with the desired `PORT` and
`SDK_MODE`. Point harness 1.34.0 at that listener and an available local mock port.
