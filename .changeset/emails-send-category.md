`emails.send` takes a `category` on sends with `template_key`: `PostHog::Emails::TRANSACTIONAL` for transactional email with no category, or a `PostHog::Emails::MessageCategory` with a `key`, `type` (`marketing` or `transactional`), `name` and optional `description`. Leave it out for transactional email with no category, as before, or, when code-send categories are enabled for the project, for the transactional category of the template that `template_key` names (when categories are disabled for the project, PostHog sends no per-send category override: a matching saved template still uses its workflow's stored configuration, and a transactional-enabled template in a marketing category still returns `marketing_template`). An explicit `MessageCategory` returns `categories_not_enabled` when categories are unavailable for the project (and HTTP 400 on an older PostHog server). PostHog refuses `TRANSACTIONAL` on a transactional-enabled saved email template in a transactional category with `category_mismatch`, and refuses a send whose `template_key` names a transactional-enabled saved email template in a marketing category with `marketing_template` (a saved template never enabled for transactional sends returns `template_not_transactional`). PostHog creates the category the first time a send names its key, and uses its `name` and `description` only then; change them later in PostHog. A marketing email skips recipients who opted out, can't have `cc` or `bcc` (`copies_not_allowed`), can't carry attachments (`workflow_can_wait` on a verified sender because marketing sending limits can hold delivery, or `sandbox_fields_unsupported` when using the PostHog test sender), and needs a clickable link whose `href` points to `{{ unsubscribe_url }}` (with optional query string or fragment) in `html` (or `{{ unsubscribe_url }}` in `text` when there is no `html`).
